## 1. Лабораторийн ажлын зорилго

Энэхүү лабораторийн ажлын зорилго нь Exploratory Testing буюу хайгуулын тестийн аргыг ашиглан номын жагсаалтын веб аппликейшний ажиллагааг шалгах, алдаа болон доголдлыг илрүүлэх, тестийн үр дүнг баримтжуулахад оршино.

Туршилтын явцад хэрэглэгчийн интерфейс, хайлтын үйлдэл, өгөгдөл нэмэх, оролтын утгын баталгаажуулалт болон API-ийн хариу үйлдлийг шалгасан.

## 2. Туршилтын хамрах хүрээ

Туршилтыг дараах чиглэлээр гүйцэтгэсэн.

- **Couch Potato Testing:** Оролтын талбаруудад хоосон, буруу, хязгаарын болон давхардсан утга оруулж шалгах.
- **Supermodel Testing:** Хайлтын ажиллагаа, хайлтын үр дүн, текстийн урт, үсгийн том жижиг ялгаа болон жагсаалтын харагдацыг шалгах.
- **Saboteur Testing:** Буруу болон хүлээгдээгүй өгөгдөл оруулж, системийн алдаатай нөхцөлд үзүүлэх хариу үйлдлийг шалгах.
- **API Testing:** Номын жагсаалт авах, ном нэмэх хүсэлт болон буруу өгөгдөлтэй хүсэлтийн хариуг шалгах.
- **Code Inspection:** Эх кодыг шалгаж, илэрсэн асуудлын боломжит шалтгааныг судлах.

## 3. Ашигласан хэрэгсэл

## 4. Туршилтын гүйцэтгэл

Туршилтын явцад дараах асуудлууд ажиглагдсан.

- Хоосон талбар болон буруу утга оруулахад хангалттай баталгаажуулалт хийгдэхгүй байх.
- Он заах талбарт боломжгүй болон бутархай утга оруулахад хүлээгдээгүй үр дүн гарах.
- Давхардсан ном нэмэгдэх боломжтой байх.
- Хайлтын үсгийн том, жижиг ялгаанаас шалтгаалан үр дүн өөрчлөгдөх.
- Нийт номын тоо болон харагдаж буй номын тоо зөрөх.
- API буруу өгөгдөлтэй хүсэлтэд амжилттай мэт хариу өгөх тохиолдол ажиглагдах.

Туршилтын үр дүнг `session-report.md`, `bugs/` болон `evidence/` хавтас дахь тайлан, нотлох баримтуудаар баримтжуулсан.

## 5. Тестийн үр дүн

Туршилтын явцад хэрэглэгчийн интерфейс болон API-ийн ажиллагаатай холбоотой хэд хэдэн сэжигтэй доголдол илэрсэн. Зарим тохиолдолд API-ийн бодит хариу болон эх кодоос хүлээгдэж буй ажиллагаа хоорондоо зөрүүтэй байсан тул тухайн орчны ажиллаж буй хувилбар болон эх кодын нийцлийг нэмэлтээр шалгах шаардлагатай.

Алдаа бүрийн дэлгэрэнгүй тайлбар, дахин үүсгэх алхмууд, хүлээгдэж буй болон бодит үр дүнг `bugs/` хавтас дахь тайлангуудаас үзнэ үү. API хүсэлтийн нотлох баримтууд `evidence/` хавтаст байрлана.

## 9. Section E — Debrief

1. **Хамгийн үр дүнтэй туршилтын аялал:** Миний хувьд Couch Potato Testing хамгийн үр дүнтэй байсан. Учир нь хоосон талбар, буруу утга болон он заах талбарын хязгаарын утгуудыг шалгах үед системийн баталгаажуулалттай холбоотой асуудлууд илэрсэн.

2. **Аялал ба алдааны хамаарал:** Оролтын талбарын баталгаажуулалт болон он шалгахтай холбоотой асуудлууд Couch Potato Testing-ийн үеэр илэрсэн. Харин хайлтын үсгийн том, жижиг ялгаатай холбоотой асуудал Supermodel Testing-тэй холбоотой байв.

3. **Charter-аас гадуурх нээлт:** Номын жагсаалтыг шалгах явцад дэлгэц дээр харагдаж буй нийт номын тоо болон API-ийн `/api/stats` хариунд буцаж ирсэн тоо зөрж байгааг анзаарсан. Үүнийг шалгахын тулд `curl.exe` ашиглан API-ийн хариуг авч, дэлгэц дээрх мэдээлэлтэй харьцуулсан.

4. **Дараагийн сессээр шалгах зүйлс:** Зарим илэрсэн асуудлыг дахин ажиллуулж баталгаажуулах шаардлагатай байсан. Дараагийн удаа давхардсан ном нэмэгдэх нөхцөл, буруу өгөгдөлтэй API хүсэлт болон өөр орчинд алдаа давтагдаж байгаа эсэхийг илүү нарийвчлан шалгана.

5. **Playwright-аар илрүүлж болох асуудлууд:** Хоосон талбар оруулахад алдааны мэдэгдэл гарч байгаа эсэх, хайлт зөв ажиллаж байгаа эсэх, ном нэмсний дараа жагсаалт шинэчлэгдэж байгаа эсэхийг Playwright ашиглан автоматжуулж болно. Мөн нийт номын тоо дэлгэц болон API дээр ижил байгаа эсэхийг шалгаж болно.

6. **Хүний ажиглалтаар илрүүлэх асуудлууд:** Товчлуурын өнгө, мэдээллийн харагдах байдал, алдааны мэдэгдлийн ойлгомжтой байдал зэрэг хэрэглэгчийн туршлагатай холбоотой асуудлыг хүн өөрөө шалгахад илүү тохиромжтой. Автомат тест зөвхөн урьдчилан тодорхойлсон нөхцөлийг шалгадаг тул санаанд ороогүй доголдлыг хайгуулын тестээр илрүүлэх боломжтой.

7. **API тестийн ач холбогдол:** `curl.exe` ашиглан API-ийн статус код, header болон response body-г шалгаснаар веб интерфейсээс шууд харагдахгүй асуудлыг илрүүлэх боломжтой байв. Ялангуяа нийт номын тооны зөрүүг шалгахдаа API-ийн хариуг дэлгэц дээрх мэдээлэлтэй харьцуулсан.

8. **Нотлох баримтын ач холбогдол:** Илэрсэн асуудал бүрийн алхам, хүлээгдэж буй үр дүн, бодит үр дүн болон screenshot-уудыг хадгалсан. API-ийн хариуг текст файлд хадгалснаар асуудлыг дахин шалгах, бусдад тайлбарлахад хялбар болсон.

9. **Цаашдын сайжруулалт:** Цаашид илэрсэн асуудлуудыг аппликейшнийг шинээр эхлүүлсэн орчинд дахин шалгаж, баталгаажсан алдаануудыг сэжигтэй асуудлаас ялгаж бүртгэнэ. Мөн гар ажиллагаатай хайгуулын тестийг Playwright зэрэг автомат тесттэй хослуулснаар ижил алдаа дахин гарахаас сэргийлэх боломжтой.
